# Rank Peek — доповідь: як зробили і які труднощі обійшли

Дата: 2026-07-22.

## Мета

Автоматично щодня (кожні 4 год) відстежувати позиції ~200 арбітражних сайтів у Google
по бренд-кейвордах у своїх гео, і **миттєво отримувати Telegram-алерт**, якщо сайт випав
із топ-5 або зник із видачі.

## Шлях рішення (коротко)

1. **Старт:** зрілий застосунок `ai-rank-tracker-stage7` (TypeScript + PostgreSQL + Docker,
   повний пайплайн: snapshot → diff → події → Claude → звіт → Telegram). Запустили mock-тест.
2. **Реальні дані через DataForSEO** (SERP API на datacenter-проксі).
3. **Тупик:** DataForSEO показував сайти як «немає у видачі», хоча GSC і сам користувач
   бачили їх у топ-3.
4. **Глибоке дослідження** (workflow, 109 агентів, 26 джерел): це задокументована
   анти-бот поведінка — Google віддає скраперам деградовану видачу по нових брендових
   запитах; резидентні проксі це **не гарантовано** лагодять; GSC точний, але створює
   footprint. Єдиного «drop-in» рішення немає.
5. **Розворот:** реальну видачу «як бачить сам користувач» дає **тільки його власний
   браузер**. Тому побудували **розширення Chrome «Rank Peek»**, яке читає SERP прямо з
   екрана користувача, у його сесії/гео.
6. **Фінал:** авто-прохід кожні 4 год + Telegram-алерти + завантаження списку з CSV +
   таблиця з датою останньої перевірки по кожному сайту.

## Труднощі та як обійшли

| # | Проблема | Причина | Рішення |
|---|---|---|---|
| 1 | `npm ci` падав у Docker-білді | `package-lock.json` урізаний до 1 платформи (~8 optional-бінарників замість ~70) | Чиста регенерація lock-файлу — повний портативний набір усіх платформ |
| 2 | Пайплайн падав на diagnostics/AI: `limit must be 1..1000` | Сервіси передавали `limit: 10_000` у репозиторій із max 1000 | Хелпер `collectAllPages()` — пагінація сторінками по 1000 без мовчазного обрізання |
| 3 | pg `DeprecationWarning` при імпорті | `loadState` робив 3 запити через `Promise.all` на **одному** транзакційному з'єднанні | Серіалізували запити (одне з'єднання не вміє паралельні) |
| 4 | DataForSEO: 3/10 задач `permanent_error` (HTTP 403) | Транзієнтний throttle-403 класифікувався як permanent → втрата оплачених результатів | Зробили HTTP 403 retryable (401 лишили permanent), знизили конкурентність fetch |
| 5 | **Головна:** DataForSEO показував сайти OUT, а насправді вони в топ-3 | Google віддає datacenter-скраперам **деградований SERP** (se_results_count 2-9, спам youtube/trustpilot) по нових брендових запитах | Довели, що це не наш баг (парсер/гео/матчинг ОК, контрольний запит працює), і **змінили метод збору**: не API, а власний браузер |
| 6 | Дані «холодного» скрапера ≠ те, що бачить користувач | Персоналізація + реальний IP країни; API це не відтворює | Розширення читає DOM видачі **в браузері користувача** (його сесія/логін/гео) |
| 7 | Парсер пропускав `play.google.com` → зсув позицій | Занадто широкий фільтр `.google.com` вирізав легітимні результати-піддомени | Фільтр лишає лише сам пошуковий хост, результати-піддомени рахуються |
| 8 | Авто-прохід відкривав `q=undefined&gl=undefined` | Колізія ключа сховища: стара версія зберегла `targets` як рядки, нова читала як об'єкти | Розвели ключі (`sweepTargets`), додали валідацію форми + захист від undefined |
| 9 | «Запустився тільки 1 запит» | Пауза між запитами 25 с (анти-CAPTCHA) — просто ще не дійшло до 2-го | Зробили паузу **налаштовуваною** (дефолт 15 с) + пояснили |

## Підсумкова архітектура

```
CSV зі списком сайтів
   → завантаження в розширення (парсинг, geo→gl/hl, second keyword → окремі цілі)
   → авто-прохід кожні 4 год у ТВОЄМУ браузері (твоя видача)
   → зчитування позиції з DOM (#rso)
   → порівняння з минулим разом (persist lastPositions/lastChecks)
   → якщо випав нижче топ-N або зник → миттєвий Telegram-алерт (по кожному сайту)
```

**Файли розширення:** [browser-extension/](browser-extension/) — `content.js` (читає DOM),
`background.js` (оркестратор + алерти + розклад), `popup.*` (UI/CSV/налаштування).

## Функції готового розширення

- **Авто-прохід кожні N год** (chrome.alarms) + ручний запуск, людський темп (налаштовується).
- **Завантаження списку з CSV** (формат `GEO,Brand,Domain,keyword,second keyword,…`):
  бере лише `is_active=TRUE`, витягує hostname, розгортає `keyword`+`second keyword`,
  мапить країну → `gl/hl`.
- **Telegram-алерти по кожному сайту** на зміні стану: випав нижче топ-N / зник із видачі /
  повернувся. Токен+chat_id налаштовуються, є тест.
- **Таблиця в popup**: усі цілі з позицією (кольорові пігулки) і **датою/часом останньої
  перевірки** по кожному сайту; бейдж статусу; вбудований короткий гайд.
- **Експорт результатів**: `⭳ CSV` (таблиця: сайт, кейворд, гео, позиція, дата, час, домен,
  хто #1) і `⭳ JSON` (повний дамп із топ-10).
- **Експорт конкурентів** `⭳ Конкуренти`: по основному кейворду кожного сайту — **топ-5
  конкурентів** із їхніми позиціями (виключає власні домени й «шум» типу trustpilot/app store).

## Ключовий інсайт

Для нових брендових сайтів **нейтральні SERP-скрапери (навіть платні) ненадійні** — Google
годує їх деградованою видачею. Джерело правди — або **Google Search Console** (точно, але
footprint), або **власний браузер** (те, що реально бачить користувач). Ми обрали браузер:
безкоштовно, без проксі, без footprint, і показує саме твою видачу.

## Результат

Робоча система «під ключ»: CSV-керований список → моніторинг кожні 4 год по реальній
видачі → персональні Telegram-алерти про падіння з топ-5 / зникнення, з датою й часом
останньої перевірки по кожному сайту. Плюс вивантаження результатів у CSV/JSON і окремий
експорт **топ-5 конкурентів** по кожному сайту — усе без проксі, без footprint, безкоштовно.

## Що можна додати далі

- Колонка «вчорашня позиція / зміна ±» у звіті та в Telegram.
- Гео через VPN-перемикання (для «холодної» країни на додачу до персоналізованого зрізу).
